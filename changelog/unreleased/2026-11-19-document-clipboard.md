- **A rich field's HTML carries the marks and paragraph attributes a word processor has.** `to_html`, `selected_html` and `paste_html` now write `Mark::Family`, `Mark::Size`, `Mark::Color` and `Mark::Highlight` as inline CSS, and a field that holds a document (one with paragraph attributes or ids) reads them back (`font-family`, `font-size` in points, `color`, `background-color`; `background` and Word's `mso-highlight` are read too), `Mark::Baseline` as `<sub>` and `<sup>` (and `vertical-align`), and a paragraph's alignment as `text-align` (the `align` attribute is read too). `TextEdit::set_html_styles(&[HtmlStyle { style, tag, class }])` says which element each paragraph style is, so a heading copies as `<h1>` and a title as `<p class="title">`, and pasting such an element gives the paragraph that style where it used to make the text bold. Pasted paragraphs keep their style and alignment; the first and the last join the paragraph they land in and take its attributes unless it holds nothing on that side. CSS colours read as `#rgb`, `#rrggbb`, `rgb()` and the names Word and browsers write; lengths as `pt` and `px`.
- **`rune::text::alias_family(name, family)`** draws runs whose span or `Mark::Family` names `name` in the registered family `family`, so a document's Calibri shows in a bundled metric-compatible font and keeps its name.
- **A headless script run has a clipboard of its own.** A script's copy (`cmd+c`, `Tx::copy_rich`) now reaches its paste (`cmd+v`, `Tx::request_paste`) through an in-memory clipboard, never the system's. Before, a headless copy went nowhere.
- **In a field that holds a document, the caret before a paragraph's first character takes that character's marks**, so text typed in front of a bold heading is bold and `active_marks` says so, as in a word processor. Other fields still start a line plain.
